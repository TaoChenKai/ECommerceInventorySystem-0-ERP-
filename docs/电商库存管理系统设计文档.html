1项目概述

1.1 项目背景

经营者主业为游戏 / 3D 设计与建模，副业经营电商小店。当前使用「秒账」管理库存，但该软件收费偏高、功能与体验欠佳；市面主流电商 ERP（如旺店通、聚水潭等）功能虽强，但采用订阅制收费，且按平台订单量抽佣，前期资金压力大、长期被「卡脖子」。

1.2 项目目标

  • 自研自部署：建设一套完全自主掌控的库存管理系统，源码与数据均归经营者所有，无订阅费、无抽佣。
  • 多端互通：PC 与手机浏览器实时同步，一套代码、随处访问。
  • 对标旺店通：以旺店通核心能力为蓝本，逐步覆盖商品、库存、价格、财务、供应商、订单、电商对接等能力。
  • 可扩展：预留电商平台对接、自定义属性扩展的架构，随业务成长平滑演进。

1.3 对标对象

以「旺店通 ERP 企业版」为功能标杆，重点对标其 商品管理、订单管理、库存管理、采购管理、财务管理、店铺/平台对接 六大模块，并针对小店场景做减法，优先落地核心刚需。

2需求分析

2.1 业务规模

维度规模说明
款式（SPU）约 300 款样式相似、暂可按款拆分管理
每款规格（SKU）2 ~ 十几个不等款式不同规格数不同，系统不设上限（5~6 仅为估算均值）
SKU 总量约 1500 ~ 1800 个现代数据库完全无压力

2.2 核心诉求

  • 每个产品拥有专属 ID + 二维码 / 条形码，扫码即可查看商品信息与实时库存。
  • 卖出一件扫一下即出库，自动扣减库存，并沉淀销售流水。
  • 自动分析哪些款好卖、哪些积压滞销，辅助经营决策。
  • 记录成本价、销售价、活动价（双11 / 618 / 七夕）、平台补贴价，系统自动核算毛利，无需手动计算。
  • 覆盖物流成本、财务对账、供应商管理等电商刚需。
  • 支持自定义属性（名称、型号、类型、重量、美工图、实体图及任意扩展字段）。
  • 后期对接小红书 / 抖音 / 拼多多 / 天猫 / 海外平台等电商渠道。
  • 支持打印标签 / 单据：商品二次包装时，用打印机打印含名称、信息二维码、售价的标签贴到新包装。
  • 账号登录 + 多级权限：账号密码进入系统防泄露，老板 / 管理员 / 员工三级权限，员工只填看、管理员可配字段、老板全权。
  • 票据 / 回执单打印：出货时打三联单（存根 / 记账 / 客户联），给客户回执、自留实体备份，方便后期复盘。
  • 销售渠道追踪：每笔出货标记来源（实体店 / 天猫 / 淘宝 / 拼多多 / 京东 / 抖音 / 海外等），按平台统计销量与毛利，指导「专攻哪个平台」。

2.3 数据迁移

现有数据存储于「秒账」，该软件支持导出与导入。系统将提供「秒账数据一键导入」功能：经营者导出 Excel / CSV 后，拖入系统即可自动建立商品、规格与库存，实现无缝搬迁。

3核心概念（SPU / SKU）

这是整个系统的地基。要管理「同款式、多规格」的商品，必须区分两个层级：

SPU（款式 / 商品）

一个「款式」为一个 SPU。例如「T恤 A 款」，拥有同一套名称、主图、详情、类型、重量等公共信息。

SKU（规格 / 单品）

SPU 下的每个可独立售卖、独立管理库存的规格。例如「T恤 A 款 · 红色 · XL 码」，才拥有独立条码 / 二维码与独立库存。

款式 SPU（T恤 A 款） ├─ SKU：红色 · XL 码（条码 001，库存 12） ├─ SKU：红色 · L 码（条码 002，库存 20） ├─ SKU：蓝色 · XL 码（条码 003，库存 8） └─ SKU：蓝色 · L 码（条码 004，库存 15）
为什么这么分？ 扫码时识别的是 SKU（具体规格），扣减的是该 SKU 的库存；销量统计既可按 SPU 汇总（哪个款卖爆），也可按 SKU 汇总（哪个码积压）。这套模型一旦定好，活动价、电商对接、采购补货全部顺理成章。规格数量完全自由：每款挂 2 个、5 个、十几个 SKU 都行，不设上限、不要求统一；新增规格只在 SKU 子表加一行，款式与老数据纹丝不动。

5功能模块详细说明

5.1 商品管理

管理 SPU 与 SKU 两级档案。SPU 承载公共信息（名称、型号、类型、重量、主图、美工图、实体图、详情）；SKU 承载规格信息（尺寸 / 颜色等 + 独立条码 + 独立库存）。支持自定义属性：经营者可随时新增任意字段（材质、产地、风格等），系统不锁死。

5.2 条码 / 二维码管理

每个 SKU 自动生成唯一编码，支持生成二维码与条形码图片，可直接打印张贴。扫码枪与手机摄像头均可识别，扫码即定位到对应 SKU。

5.3 出入库与库存

  • 入库：采购到货、退货回库、盘点调整。
  • 出库：销售出库、报损、调拨。
  • 每一笔变动均写入流水，库存由流水累加而成，账实可逐笔追溯。
  • 库存预警：低于阈值提醒补货、高于阈值提醒积压。

5.4 价格与毛利核算

系统记录成本价与销售价，并预留活动价格引擎（第二版）：为每个活动（双11 / 618 / 七夕 / 平台补贴）配置规则，核算时自动套用，直接输出实际售价、平台补贴、物流成本、最终毛利，全程无需手动计算。

5.5 财务对账（第一版重点）

  • 平台对账、快递对账、支付宝 / 微信对账。
  • 应收 / 应付管理、结算管理。
  • 自动生成利润表、销售明细报表。

5.6 供应商管理（第一版重点）

  • 供应商档案：名称、联系方式、供货品类。
  • 进货记录：每次采购留痕，支持比价。
  • 到货验货记录。

5.7 数据分析

提供库存状况、出入库统计、热销 / 滞销排行、毛利分析等报表，辅助「哪些该补货、哪些该停产」的经营决策。

5.8 标签打印（第一版重点）

商品到货后需二次包装，不能直接用厂家原包装出货，因此需用打印机重新打印标签，贴到新包装上。系统提供完整标签打印能力：

  • 标签内容自定义：商品名称、详细数据二维码、销售价格、SKU 编号、规格、材质、生产日期等，想打哪些字段自己勾选。
  • 信息二维码：标签上生成「含商品完整信息的二维码」，贴到新包装后扫码即可还原该商品全部档案（与扫码入库同一套编码）。
  • 连接电脑打印机：支持常见标签 / 热敏打印机（USB、蓝牙、网络），标签尺寸可配（40×30、50×30、60×40mm 等）。
  • 批量打印：勾选多个商品一键批量打印标签，也支持打印入库单、出库单等单据。

流程：录入商品信息 → 选择商品 → 预览标签 → 打印 → 贴到新包装。扫码、打印、入库一气呵成。

5.9 账号与权限管理（第一版重点）

系统涉及经营核心数据，账号密码登录是防泄露的第一道门。采用三级账号体系，权限自上而下收敛：

角色数量可做的事不能做的事
老板（超级管理员）1 个（唯一）查看 / 修改 / 删除一切数据；配置字段；账号管理；数据库升级；新增功能模块—（全权）
管理员多个填写数据、翻阅数据；添加基础字段（单位 / 类型 / 型号 / 功能等字典项）不能修改 / 删除核心业务数据；不能升级；不能加模块；不能管账号
员工多个填写数据（出入库录入等）、翻阅数据不能改配置、不能删数据、不能升级、不能管账号
  • 登录安全：账号 + 密码（密钥）登录，密码加密存储，可自助修改。
  • 权限隔离：不同角色可见、可操作的范围不同，员工看不到老板的配置与升级入口。
  • 操作日志（审计）：记录谁在什么时间做了什么，可追溯，防止误操作与数据外泄。
  • 自由增删子账号：老板可随时新增 / 停用管理员与员工账号，一人一账号。

第三版再进阶到数据权限、字段级权限、审批流等更细粒度管控。

5.10 票据 / 单据打印（第二版，单量上来后）

单量增大后，需要给客户纸质回执、并自留纸质存根作为实体备份。系统提供「单据打印」能力，与 5.8 标签打印共用一套打印引擎，只是打印「交易单据」而非商品标签。

  • 三联单设计：一张纸分三联——存根联（自己留档）、记账联（备份）、客户联（给客户的回执单），虚线分隔可撕分。
  • 回执单内容：商品名称、单价、数量、金额小计、合计、日期、单号，客户一目了然。
  • 单据类型：销售单（出货回执）、进货单（采购凭证）、出入库单，各自模板可配。
  • 打印机兼容：支持 A5 / A4 纸打印三联单，也支持热敏小票机打印单联小票。
  • 自动生成：开单 / 出入库时自动生成对应单据，一键打印，无需二次录入。

价值：客户拿回执、门店留存根，白纸黑字可查证；纸质备份与系统电子数据互为印证，方便后期复盘。

5.11 销售渠道追踪（第一版重点）

货从哪里卖出去的，必须记下来。多平台 + 实体店并行时，只有知道每笔出货来自哪个渠道，才能看清「哪个平台卖得多、毛利高、值得深耕」。

  • 渠道档案：维护全部销售渠道（实体店、天猫、淘宝、拼多多、京东、抖音、小红书、海外平台等），可随时自定义增删——平台会变，渠道绝不写死。
  • 出库标渠道：每次销售出库时选择渠道来源，手机扫码时顺手点一下，零负担。
  • 渠道统计报表：按渠道统计销量、销售额、毛利及占比，各平台自动排行。
  • 辅助「专攻哪个平台」：哪个月活动高、哪个平台客户多、毛利高，一目了然；集中资源深耕高产出平台，低产出平台先放一放（员工有限时尤其重要）。

为什么第一版就要做：数据从第一天开始积累。若等订单量上来再补渠道记录，历史数据已不可追，无从对比。第一版做「渠道记录 + 基础统计」，平台复购率、客户画像等深度分析放到第三版。

7技术架构

7.1 形态选择

响应式 Web + PWA（选定）

一套代码，PC / 手机 / 平板浏览器通用；PWA 可将系统「安装」到手机桌面，体验接近 App，且无需上架应用商店。

原生 App（后期 · 安卓 + 鸿蒙 Next）

订单量上来后开发原生 App，覆盖安卓与鸿蒙 Next（iOS 暂缓），采用 uni-app 与 Web 同源复用，仓库扫码体验再升一档。

7.2 技术栈

层级技术选型说明
前端Vue 3 + Vite响应式界面，一套代码多端适配
后端Python（FastAPI）轻量高效，便于快速迭代与对接 API
数据库PostgreSQL稳定可靠，支持事务与复杂查询
部署Docker + Docker Compose一键部署，环境隔离，迁移方便

7.3 部署方案

系统打包为一键部署包（Docker Compose + 启动脚本），最终落地到经营者自有的 Windows 11 服务器（该服务器同时用于 3D / 游戏云端渲染）。Docker Desktop + WSL2 运行容器，数据库与系统稳定托管，数据 100% 自有。

7.4 多端互通

系统为 B/S 架构，PC 与手机通过同一地址访问，数据实时同步；局域网或内网穿透 / 公网映射后，可在外网随时访问。

7.5 架构扩展性保障

系统按「模块化 + 可扩展数据模型」设计，从第 1 版起就为后续版本预留扩展空间，后续加功能不推倒重来、不重建数据库：

  • 数据永不重建：商品、库存、账目等老数据是资产，任何版本升级都「原地升级」，绝不要求重新录入。
  • 加功能 = 加表 / 加字段：数据库采用可扩展设计，新功能对应新表或新字段，老数据不动（如后期加「质检记录」，只新建质检表挂到商品上）。
  • 模块插拔式：财务、供应商、打印、退货、采购、电商对接等均为独立模块，加新模块不影响已有模块。
  • 升级 = 打补丁：每次升级用「增量迁移」脚本自动适配老数据，全程无感、不丢数据。
  • 规格数量自由：SPU 与 SKU 为「一对多」关系，每款挂 2 个还是十几个规格都不受限，新增规格只增行、不动款。

唯一需大改的是「核心商品模型被彻底推翻」这类极端情况，但该模型已在第 1 版定稿，基本不会发生；即便发生，也按「保留数据 + 平滑迁移」处理，不要求重录。

11风险与边界

诚实边界：电商平台对接（抖音 / 天猫 / 拼多多 / 海外等）为后期大工程，各平台开放 API 存在资质审核门槛，且部分接口可能收费。本系统前期不接入平台，先打好「商品 + 库存 + 价格 + 财务 + 供应商」地基，待订单量增长后再逐个平台推进。

关键前提

  • 秒账数据需能导出为 Excel / CSV，方可实现一键迁移（经营者已确认支持导出）。
  • 本地服务器需安装 Docker 环境（Windows 11 使用 Docker Desktop + WSL2）。
  • 外网访问需配置内网穿透或公网映射（后期按需处理）。
